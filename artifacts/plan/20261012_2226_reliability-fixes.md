# 看板四项可靠性修复实施方案

## Summary

修复刷新竞态、分页静默截断、配置保存失败状态不一致、全部失败与部分失败混用。保留只读TAPD和分页安全上限；本次不涉及令牌字段契约或其他产品迭代。用户已明确要求修复四项问题。

## Implementation Plan

1. 刷新以递增请求序号控制提交，旧请求不能更新数据、错误、时间或加载状态；记录已加载时间范围。新范围加载期间或失败时，隐藏其他范围的旧任务；同范围失败保留数据并明确标注旧数据。
2. 分页触顶且无法确认完整时返回显式截断信息，聚合保留已拉取任务；新增完整/部分/全部失败状态，成功空结果与失败分开。
3. 配置更新采用串行保存、成功后提交内存；失败不修改已确认配置，在设置页展示错误，消化UI事件中的拒绝。
4. 看板分别展示全部失败、部分失败、分页截断和旧数据提示；全部失败不更新最后成功刷新时间，不显示正常空数据结论。

## Test Plan

补充乱序成功/失败、加载状态、分页触顶与刚好到达上限、全部失败和成功空结果、配置保存失败及连续更新、看板错误与旧数据范围隔离的回归测试。执行完整pnpm test、pnpm build及git diff --check，使用iTerm并保存日志。

## Assumptions

最后刷新时间表示最近一次至少有工作项数据源成功的刷新。部分成功只使用本轮成功数据；全部失败保留上轮数据，但数据范围不同则不展示。分页触顶不会自动突破安全上限，提示用户缩小范围。只测试模拟接口与本地构建，不使用真实令牌。
