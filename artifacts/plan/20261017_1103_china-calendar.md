# 中国节假日及调休实施方案

## Summary

新增“中国节假日及调休”总开关，下方按年份展示可点击的缓存状态标签。看板与工时共用中国日历：休假按非工作日处理，周末补班按工作日处理。

移除原手动日期维护功能及其配置效果。成功获取的数据永久缓存，只有用户点击对应年份的状态标签时才刷新。

## Implementation Plan

### 设置与状态交互

- 总开关独立保存，保存成功后立即生效；失败恢复原勾选状态。默认关闭。
- 年份列表展示当年、已有缓存年份，以及访问看板或工时所需的年份，按年份倒序排列。
- 绿色“已缓存”表示已成功获取并持久保存有效数据；红色“未获取”表示没有有效缓存。
- 状态标签使用原生按钮，支持鼠标和键盘操作；点击后强制刷新对应年份，不另设刷新按钮。
- 请求期间显示“获取中…”并禁止重复点击，颜色仍反映缓存是否存在。
- 刷新成功更新缓存和获取时间；失败显示原因，保留旧缓存及其绿色状态。
- 显示数据来源与获取时间；保留成员请假豁免、规定工时及结束状态配置。

### 数据来源、缓存与兼容

- 使用 NateScarlet/holiday-cn，优先 jsDelivr，失败后尝试 GitHub Raw。
- 新增仅接收年份的 Tauri 异步请求命令，固定来源地址，阻塞 HTTP 放入后台线程；浏览器开发模式请求相同来源。
- 配置版本升至 v3，新增 AppSettings.chinaCalendar，保存总开关及按年份缓存的数据、公告链接、获取时间。旧配置默认关闭，忽略原 calendarOverrides。
- 缓存无有效期。重启、页面切换、重新勾选、日期变化均不刷新已有有效缓存。
- 启用时自动获取尚无缓存的当年数据；首次访问其他年份按需获取。自动获取失败后由标签手动重试，避免重复自动请求。
- 同年份合并并发请求；新数据校验与保存成功才替换旧缓存，持久化失败明确提示。
- 校验文件年份、日期及 isOffDay，转换为 { working, name } 映射；允许文件包含上一年日期。涉及 12 月时补查次年文件，较后年份公告覆盖较早安排。
- 无缓存且获取失败时暂按普通周历，在相关页面提示受影响年份。次年补充文件尚未发布不使本年缓存失效。

### 看板与工时联动

- 新增共享纯函数 isWorkingDay，开启时使用线上安排，其余日期按普通周历判断。
- 看板表头和背景按非工作日标灰，补班周末取消灰底；任务日期与跨度保持原逻辑。
- 工时计算及 Worker 输入增加可序列化日历；每日目标、分配日期、末尾休息日加班共用判断。
- 覆盖展示日期及预测所需完整有效任务区间，确保跨年和局部查询一致。
- 个人请假继续使当日目标为零；已有实际工时和现有加班分配规则保持有效。
- 日历变化复用 TAPD 快照重算，计算身份校验防止旧结果覆盖最新结果。

## Test Plan

- 配置迁移、开关保存失败恢复、旧手动日期失效、其他设置保留。
- 标签红绿状态、点击和键盘刷新、防重复、成功及失败提示。
- 永久缓存、重启复用、首次缺失年份自动获取、失败手动重试及刷新失败保留旧缓存。
- 普通周历、2026-10-01 休假、2026-10-10 补班、跨年及次年文件补充。
- 看板与工时一致、个人请假、休息日加班及任务完整区间计算。
- 运行前端测试、构建、Rust 测试，并在桌面生产包验证同步、持久化与离线行为。

## Assumptions

- 使用中国大陆全国性安排，不保留地方或公司手动覆盖。
- 关闭只停用日历，保留缓存，再次开启复用。
- “已缓存”表示有效数据持久保存，最近一次刷新错误单独显示。
