# TeamSight P1b 实施方案

## Summary

依据已确认的技术方案 v1.2 与分阶段执行方案实施 P1b。用户已确认 P1a 完成并授权进入 P1b；真实 TAPD 写入验收限定项目 `62119705`，使用带有“TeamSight P1b 验收”标记的新建需求和任务。

交付需求/任务基础写入、操作目录与项目元数据、复合排期/工时分析、可解释风险、MCP Apps 分析视图、SVG/PNG/HTML/Markdown/CSV/JSON 产物。完成后停在 P1b 验收点；P1c 的发行、Windows 实机、宿主定时和旧 App 退役不在本阶段实施。

## Implementation Plan

1. 将现有工时计算、中国日历和甘特布局迁入 `packages/core`，旧 App 使用同一实现。保留成员顺序、小时请假、累计扣减、多负责人、日期窗口和未知量口径。
2. 扩展 `packages/tapd`：固定操作目录、story/task/bug 读取、需求与任务 POST 表单写入、项目字段/成员元数据、完整分页、全服务并发 3 和有界读取重试。写入不自动重试。
3. 扩展 SQLite 版本化迁移：操作幂等回执、快照/分析/产物元信息；大快照和产物独立保存。写前校验项目范围、操作范围、字段/身份/状态；更新比较字段摘要。请求发出后无法确认的操作保留 `unknown`，重启恢复不重复发送。
4. 分开查询每日实际与未结束工作项累计花费；按配置成员获取完整工作项，带分页、覆盖、来源时间和缺失原因。图表、工时、风险与固定报告通过同一 `analysisId` 复用确定快照和规则，完整缓存保持来源时间，写入后失效缓存。
5. 增加分析 Apps 资源：日期与成员筛选、甘特图、每日工时、明细和风险追溯。资源单入口自包含构建，通过宿主桥访问服务。
6. 甘特布局同时生成 SVG 与 PNG；宽图/多行按页输出。固定报告含目标、实际、预计、差额、当前排期、风险和数据限制；HTML 转义外部数据，CSV 处理公式注入。通过 MCP 资源返回可读取产物及 MIME/大小/分析来源。

## Test Plan

- 同一输入验证旧 App 与共享核心；保留既有前端回归并构建旧 App。
- TAPD 目录、真实 POST 方法/表单编码、字符串 ID、分页/重复页/截断、读取重试、写入单次发送、字段与授权校验。
- 幂等键重放/参数冲突、并发提交、修改冲突、超时 unknown、读回不一致、重启恢复和缓存失效。
- 工时每日实际/累计独立、重复记录、缺失身份、请假、调休、今天不作不足风险、部分/失败数据与来源时间。
- MCP 多连接工具/资源、同 analysis 的 Apps/图表/报告、一致的 HTML/CSV 转义、中文 PNG 与大图分页。
- 使用指定项目 `62119705` 真实创建并修改各一个测试需求/任务，记录远端 ID 与读回结果，不删除既有数据。
- 当前 Codex 实际打开分析 Apps 并核对图表与工具结果；不能用 SDK 客户端测试替代宿主实测。

## Assumptions

- 凭据通过现有本机配置或系统凭据接口读取，绝不输出到日志、回执和报告；真实验收使用隔离服务数据目录。
- 需求只提供基础读写，不参与 task/bug 工时汇总。未覆盖无负责人对象时明确限制，不声称完成项目全量扫描。
- 默认业务时区 Asia/Shanghai；显式分析日优先。当前日期仅报告进度，不提前判定历史工时不足。
- TAPD 不提供原子条件更新时，字段摘要只能降低并发风险。服务幂等不能提供远端恰好一次保证。
