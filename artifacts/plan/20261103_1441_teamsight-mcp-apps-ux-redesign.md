# TeamSight MCP Apps 体验优化方案

## Summary

TeamSight 的使用入口是对话。用户通过自然语言说明要处理的配置、人员、项目、日期和目标；Agent 负责理解范围、调用 MCP 获取或计算数据，并在需要直接操作或查看图形时打开对应的 MCP Apps。卡片聚焦本次任务，不承担完整桌面应用的导航、查询和报表工作。

本方案保留已确认的设置能力、数据计算和甘特图的任务／工时双层交互，重点调整信息架构、卡片打开方式、视觉与交互。仅在方案确认后实施；本次不修改业务代码。

## 当前问题及需求理解

当前结论来自用户试用反馈、工作树源码和已有浏览器 SDK 验收截图；截图使用隔离数据，不代表本轮实际 Codex 原生宿主的验收。

1. 设置页把团队、工时、项目、成员、分组、TAPD 连接、请假、状态、日历、写入范围、旧配置导入和基础查询同时放进一张长表单。用户要找的内容不突出，项目和成员行在窄宽度下大量换行；整个表单统一保存，用户难以判断本次实际修改的范围。（见 [FormalSettings.vue](../../apps/mcp-ui/src/FormalSettings.vue:161)）
2. 甘特图页面同时放置查询日期、人员范围、分析日期、开始／刷新、三种页面视图、筛选、图层切换、工作项明细和六种导出，图形只是其中一部分。已有截图显示图形的有效内容集中在左侧，小范围数据旁边留有较大空白。（见 [Analysis.vue](../../apps/mcp-ui/src/Analysis.vue:125)、[GanttLayers.vue](../../apps/mcp-ui/src/GanttLayers.vue:22)）
3. 用户希望在对话里表达意图，让卡片只呈现完成当次任务需要的内容。针对“打开项目配置”，项目配置之外的表单、导航入口和基础查询均不渲染；普通“打开设置”则需要一种能找到各类配置的入口。
4. 甘特图卡片的操作区仅保留任务优先／工时优先切换；继续支持图上前景对象的点击、悬浮与详情。成员、项目和日期范围通过对话确定，卡片不提供筛选入口。查询、风险解释和导出也由对话按需发起。

## Implementation Plan

### 1. 对话与卡片的职责

| 用户意图 | Agent / MCP | Apps |
| --- | --- | --- |
| “打开项目配置” | 将目标配置类型传给设置入口 | 只渲染项目配置和该表单的必要操作 |
| “打开设置” | 未指定类型时打开配置入口 | 展示配置分类及简短状态，选中后只显示该类配置 |
| “配置 Token”或因缺 Token 阻断 | 打开连接配置，保持待处理的原请求 | 只展示令牌及必要连接状态；保存成功后通知宿主继续原读取 |
| “看团队本周甘特图” | 按对话解析业务时区、日期和人员／项目范围，先获取同一份分析结果 | 展示范围、双层图、模式切换和详情；不提供筛选入口 |
| “换成下周／换个团队” | 通过对话重新获取或复用符合范围的分析 | 新结果对应的卡片展示实际范围；不可把卡片内缩小显示范围冒充重新取数 |
| “导出甘特图／工时报表” | 按用户指定格式调用现有导出能力，说明导出范围 | 甘特图卡片不常驻导出按钮 |
| “分析进度风险” | 调用相关结果并在对话解释依据 | 甘特图不常驻独立风险页签 |

默认指令与工具描述明确以上路径；不把本轮改造扩展为 skills 编写。工具能力和原有工具名继续保留，界面精简不意味着删除 MCP 基础能力。

### 2. 设置卡片的信息架构

建议采用“配置入口 + 定向表单”：无指定目标时显示分类列表；有明确目标时直接进入目标表单，其他类型不渲染，也不展示类型切换导航。分类仅是交互上的划分，不是新的权限隔离。

| 目标及常见说法 | 卡片显示内容 | 不在此卡片展示 |
| --- | --- | --- |
| TAPD 连接／令牌 | 凭据是否已配置、当前用户、令牌输入和保存；连接地址等高级连接项仅在此类设置中按需展示 | 项目、成员、工时和业务查询表单 |
| 项目配置 | 同步项目；项目名称、别名、颜色、启停、排序及已有项目管理能力 | 成员、分组、工时等表单 |
| 成员配置 | 查找与选择成员、身份信息、启停、排序、删除本地身份 | 项目和工时表单；不自动把新发现成员加入团队 |
| 分组配置 | 成员多分组、唯一默认分组、测试人员组和分组成员 | 项目、连接等表单 |
| 工时与日历 | 每日规定工时、业务时区、节假日／调休、请假及完成状态配置；可按明确子目标只展开相应内容 | 项目、成员和令牌表单 |
| TAPD 写入范围 | 允许写入的项目、操作和字段，以及当前范围说明 | 其他设置表单；项目启用不会自动扩大写入范围 |
| 其他设置 | 团队名称、原有查询范围／类型、旧配置导入等现有能力按合理分类保留 | 不把调试式基础查询塞回普通设置表单 |

普通“打开设置”只展示分类入口及必要的状态摘要，不同时展开全部表单。用户选定分类后进入对应内容；如果用户明确说了更具体的子目标，例如“节假日配置”，优先只打开该内容。不同类型同时被明确要求时，建议分别打开针对性的卡片，避免重新组合成一个长页面。

项目项以名称为主，每项清晰展示启用、颜色和别名；排序、同步、编辑等操作有明确反馈。成员发现应区分搜索候选、确定身份和加入分组三个动作；分组界面说明一个成员可以属于多个组，默认组唯一。身份、项目 ID 和写入范围等信息仍可查看，避免因视觉简化导致配置能力丢失。

保存采用当前卡片所属配置的草稿和明确的“保存”操作。仅提交本次修改的字段：对于内部共用对象如 hours、tapd，需要在服务端或提交前基于最新快照进行字段级合并并校验修订，不能用局部对象覆盖其他子字段。成功后显示已保存，失败保留草稿和明确原因；多卡片或其他会话造成修订冲突时，提示重新读取并处理差异，不静默覆盖。

项目同步、成员发现、日历刷新和旧配置导入属于已有立即执行的动作，会改动持久状态或重新读取快照。界面需显式说明该动作立即生效；存在未保存草稿时先要求保存或放弃，避免刷新快照吞掉编辑内容。提交令牌仍只经 Apps 表单和系统凭据库处理，不在对话、工具摘要或日志中回显。令牌保存后项目与身份初始化失败时显示部分完成和可重试状态，不伪称原请求已继续。

### 3. 甘特图卡片

**卡片组成：**

- 一行清晰标题和范围摘要：人员或团队、实际起止日期、必要的项目范围、数据来源时间与完整性状态。数据不完整时直接显示醒目说明。
- 常驻一个任务优先／工时优先切换；默认为任务优先。用户已明确说“工时优先”时，以该模式打开。
- 不提供成员、项目、日期等筛选入口或控件；需要改变范围时，由用户在对话提出，Agent 获取相应数据并展示结果。
- 甘特图本体与点击后的任务／每日工时详情。未排期任务的实际工时仍参与每日工时层，未排期任务清单可通过对话查询，不在图表中增加入口。
- 正常图表不常驻开始分析、刷新、单独的每日工时页、风险页、工作项全集、六个导出按钮及其预览。对话中需要这些结果时调用原有工具处理。

**双层语义：**

| 模式 | 前景：清晰且可交互 | 背景：淡化且不交互 |
| --- | --- | --- |
| 任务优先（默认） | 任务排期和完成状态；悬浮及点击查看任务 | 每日工时 |
| 工时优先 | 每人每日工时；悬浮及点击查看实际、预计、目标、差额和贡献任务 | 任务排期和完成状态 |

两层共用人员、日期、分析结果和布局；背景层不接受鼠标点击、悬浮详情或键盘焦点。任务详情保留关联需求、负责人、状态、排期、预估／实际／剩余和 TAPD 链接；工时详情保留实际、预计、目标、差额与贡献任务，并正确区分缺字段、未知值和数据不完整。

**图形布局与样式：**

- 给图表优先空间；按宿主可用宽度自适应，常见一周范围优先完整可读。月份或人员较多时在图表内部横向／纵向滚动，固定或同步人员名称与日期表头；不让整张对话页面因时间轴无限变宽。
- 日期列有合理最小宽度，按可用宽度填充但不把短任务无意义拉长；长任务名截断后仍可通过悬浮、焦点和详情查看完整名称。图形、日期列与工时贡献对齐。
- 清晰标识今天、周末／休息日、已完成状态和项目颜色；实际、预计、缺口不能只依靠颜色区分，增加可读文字或图例。任务进度只表达已知状态，不推断不存在的完成百分比。
- 跟随宿主字体、浅／深色主题及中性背景，主要操作和选中状态始终使用指定的橙色主色；宿主未提供相关主题值时使用可读的回退色。统一间距、层级、控件高度、悬浮与焦点样式。小屏／窄侧栏下优先可读，不把所有控件挤成多行。
- 详情根据容器宽度采用图下展开或侧边区域；选中对象可关闭，切换模式后不会把背景对象留在可交互状态。链接通过宿主打开 TAPD。

**范围、数据与模拟：**

- Agent 以用户给定日期、人员、项目生成分析，传入相同 analysisId 打开图表；图表直接读取结果，不让用户重新填入已在对话说过的条件。用户只说“打开甘特图”时，沿用现有默认的业务时区本月和默认团队，展示实际采用的范围；缺少必要配置或目标不明确时在对话中说明并打开对应配置。
- 用户通过对话调整日期、成员或项目范围。Agent 可按现有快照覆盖情况复用快照或重新查询，再打开对应范围的结果；不得把收窄范围冒充刷新 TAPD。项目范围内的数字明确为所选项目贡献，不能误读为成员全项目容量或工时达标结论。
- 图表的数据读取必须覆盖所请求范围的完整结果，而不是仅首批 20 名成员／200 项任务。采用自动分批或适量虚拟化；如果仍有未加载或源数据缺口，明确显示，不把空白或部分结果当作完整。不同请求的异步响应不得让旧范围覆盖新范围。
- 普通排期／紧急模拟继续使用原 calculationId 和候选；模拟结果显示“模拟、未写入 TAPD”的只读标识。候选切换及调整前后比较通过对话发起，按需展示对应结果，不在甘特图中增加切换或对比控件。结果过期时提示在对话重新计算，不显示过期内容为最新事实。
- 导出沿用现有工具和原分析快照；当前导出为完整分析范围。用户在对话中要求导出特定人员、项目或日期时，应说明当前能力边界或先生成与所需范围一致的分析，不声称已导出该范围的视图；不能把基线导出冒充模拟结果。
- 宿主支持时将当前选中任务或每日工时的非敏感上下文同步给 Agent；不能依赖该事件一定即时触发 Agent 回复。宿主不支持时卡片本身仍可独立查看，跨轮继续操作以宿主实际能力和对话给出的范围为准。

### 4. 工具、兼容性与实现步骤

1. 定义设置分类和具体目标映射。扩展现有 teamsight_open_settings 的可选参数并更新工具描述；无参数调用继续可用。结果提供初始目标给 Apps，按照当前宿主支持的输入／结果桥加载，不依赖通过 DOM 隐藏无关表单；同步相关旧入口、配置缺失引导与文档。
2. 将设置页拆为分类入口和定向表单，保持同一持久设置、原配置修订及现有系统凭据。局部保存按字段合并，处理全局对象、立即写入动作和跨卡片冲突；不改默认项目范围、默认组、写入授权或业务计算规则。
3. 改造甘特图打开链路：Agent 按用户请求先调用现有分析或模拟工具，再通过 teamsight_open_analysis 引用结果；初始模式及用户在对话中指定的范围作为打开结果的上下文，不生成卡片筛选控件。无参数调用继续有可用的默认路径：按现有本月、默认团队产生并展示结果，异步加载／出错有明确反馈，不要求用户填写一组查询表单。
4. 精简 Analysis.vue，让图表与详情成为主要内容；操作区仅保留双层模式切换，模拟结果仅添加必要的只读标识。复用 GanttLayers.vue 和共享布局／工时结果，处理宿主尺寸、图层、分页和长列表；原有导出、风险及任务工具保留给 Agent。
5. 保持单文件 MCP Apps 资源和宿主桥调用要求，避免外部脚本、相对模块引用及 Vue Proxy 参数；资源 URI、工具名称及旧客户端必要兼容性保留。设置／查询的错误和数据来源保持可追溯。
6. 更新使用说明并重新构建交付包；确认后再切换已安装服务。能力语义、TAPD 数据与计算算法不因视觉改造改变；如发现范围语义或数据接口无法支撑此设计，先明确差异再决定最小改动。

### 5. UI 视觉与组件方案（补充）

下面是供讨论的设计方向和尺寸基线。它描述界面外观与状态，不是已经实现或验收通过的效果图。主色固定为用户指定的 rgb(235, 115, 45)，即 #EB732D；宿主提供浅／深主题、中性背景或字体时尽量跟随，同时保持橙色主色。其余色值是配套设计参考，仍需在实际宿主界面验证。

#### 整体方向与视觉规范

采用贴近 Codex 会话的轻量工具卡片：以暖中性色承载信息，橙色用于主操作、当前选择和交互强调，减少大面积品牌色、重复标题、厚重背景和嵌套边框。一个卡片只设置一个主要视觉中心；设置卡片以当前设置内容为中心，甘特卡片以时间轴为中心。

| 视觉角色 | 浅色参考 | 深色参考 | 用途 |
| --- | --- | --- | --- |
| 卡片背景 | #FFFCFA | #1D1A18 | 当前配置或图表卡片 |
| 次级区域 | #F8F3EF | #28211D | 表头、辅助信息 |
| 主文字 | #241B16 | #F7F1EC | 标题、主要数据 |
| 次级文字 | #665348 | #CDBFB4 | 时间、说明、范围 |
| 分隔／网格 | #E8DDD5 | #51443B | 次级分隔线和时间网格 |
| 主色／主按钮 | #EB732D，文字 #1C0F08 | #EB732D，文字 #1C0F08 | 保存、主要操作 |
| 选中背景与文字 | #FFF4EC / #A63F09 | #36251D / #FFAF80 | 模式选中、轻强调 |
| 实际工时 | #147D70 | #60BFA6 | 已有花费；配合文字／图例 |
| 预计分配 | #C45D1A | #F2A070 | 剩余工时分配；配合文字／图例 |
| 需注意 | #8A5104 / #FFF7E5 | #E7C675 / #332B1A | 数据不完整和提醒（文字／背景） |
| 错误 | #AE3026 / #FFF1EE | #F3A29A / #321D1A | 保存或取数失败（文字／背景） |

- 主按钮默认背景严格使用 #EB732D，悬浮建议 #D86423，按下建议 #D35E1B，文字均使用 #1C0F08；禁止将默认橙底上的普通文字改成白色。按钮边界、模式选择和焦点轮廓需在两种主题背景上清晰可辨；焦点建议浅色 #A63F09、深色 #F5A36E，并保持至少 2px 轮廓。
- 当前选中模式使用浅橙背景和深橙文字，结合边框或形状区分，不只依靠色彩。链接和浅色背景上的强调文字使用较深橙色 #A63F09，深色背景使用 #F5A36E。
- 实际工时使用青绿色，预计工时使用橙色系；两者配合文字、图例及形状区分。用户已配置的项目颜色继续用于任务条，不因主题调整而覆盖；完成状态、数据缺口和错误另有文字或图标说明。
- 基于设计色值的相对亮度计算：#EB732D 与深色文字 #1C0F08 的对比度约 6.26:1，而与白色约 2.99:1；主按钮悬浮和按下状态与同一深色文字分别约 5.14:1、4.80:1。具体文本、图形和焦点在真实宿主背景下仍需分别验收。

- 使用宿主系统字体栈，中文优先系统中文字体；标题 16–18px、正文和控件 14px、辅助说明 12–13px。主要信息不低于 14px，长数字和日期适当采用等宽数字，避免跳动。
- 以 4／8／12／16／24px 为间距基准；卡片内边距常规 16px、窄侧栏 12px；表单控件高度约 36–40px，圆角 8px，卡片圆角约 10–12px。1px 分隔线为主，少用阴影和多层卡片。
- 标题、主要数据、辅助说明三层区分；按钮分主操作、次级操作和危险操作。默认不显示“修订号、工具名、MCP 版本”等实现细节，除非用户需要排查问题。
- 默认、悬浮、焦点、按下、禁用、处理中、成功和错误状态需视觉区分；键盘焦点提供至少 2px 的明显轮廓。动态效果保持短促，系统启用减少动态时关闭非必要动画。

#### 项目配置卡片

内容从上到下：标题和简短状态；“同步项目”次级按钮；项目列表；本卡片的保存操作。每个项目行突出项目名称、别名和启用状态，颜色用小色点加文字／选择器展示；项目 ID 为辅助信息，不抢占主要宽度。

以下是结构示意，具体观感以设计稿和实际宿主评审为准：

```
  项目配置                                  同步项目
  管理项目的显示方式和默认查询范围
  ────────────────────────────────────────────────
  ●  消费者平台                              已启用  [开]
     别名：商城                         编辑  排序
  ────────────────────────────────────────────────
  ●  内部工具                                已启用  [开]
     别名：未设置                       编辑  排序
  ────────────────────────────────────────────────
                                    取消    保存更改
```

- 默认每行以阅读态呈现。编辑某个项目时在该行或其下方展开名称、别名和颜色控件；排序支持明确的上移／下移，键盘可操作，不要求拖拽。已有的添加／删除能力放在该类表单内的清晰次级操作中。
- 主按钮只在有未保存更改时可用；保存中显示进度，成功显示简短反馈，失败保留编辑内容并靠近对应表单提示。项目同步若会立即生效，需和草稿保存状态明确区分。
- 成员和分组界面复用同一行样式：姓名优先，工号／账号作为辅助信息，分组以小标签展示；分组设置明确默认组、测试人员组和成员多选。令牌、工时等短表单沿用相同的标题、标签、输入、错误和操作位置。
- 当卡片宽度不足以容纳一行时，名称在上，状态及操作排列在下；禁止把项目 ID、别名、颜色、多个排序按钮挤成难辨认的一整行。定向配置卡片不显示其他类别的项目或导航。

#### 甘特图卡片

内容从上到下：标题与范围、模式切换、人员与日期网格、按需出现的选中详情。范围说明使用短文字，不占据大块状态框；来源时间与完整性直接展示，部分数据或失败时显示醒目提示。

```
  团队甘特图
  默认团队 · 11月2日—11月6日 · 数据完整

  [任务优先] [工时优先]       实际  /  预计
  ────────────────────────────────────────────────
                  周一    周二    周三    周四    周五
  李明            ░░      ░░      ░░      ░░      ░░
   结算页面       ███████████
   接口联调                       ███████████
  周宁            ░░      ░░      ░░      ░░      ░░
   订单接口               ███████████████████
  ────────────────────────────────────────────────
  已选：结算页面                    在 TAPD 中查看
  进行中 · 李明 · 11月2日—11月3日
  预估 8h  ·  实际 4h  ·  剩余 4h
```

- 示意中的 █ 表示任务条、░ 表示淡化的每日工时背景；实际界面使用项目颜色、可读文字与日期网格。任务优先是默认模式，任务条为前景，能看见任务起止、已完成标识；任务条颜色来自项目配置，完成状态另用图标／文字区分。
- 切为工时优先后，不更换人员与日期布局：每日工时柱移动到前景并可点击，任务条淡化到背景。工时柱内按实际和预计分段，使用颜色加图例／文字区分；目标、差额和明细在选中详情呈现，未知或不完整不能以 0h 冒充。
- 小屏保持任务名称列和日期表头可辨认；建议名称列约 120–160px，日期列最小约 44–52px，空间不足时仅图表内部横向滚动。较宽容器可让时间轴合理扩展，避免右边大片空白；长名称截断后通过悬浮、键盘焦点和点击详情显示完整内容。
- 点击前景任务或每日工时后展示紧凑详情；宽容器可在右侧展示，窄容器在图下展示。悬浮只提供摘要，详情承载较长内容。切换模式时清理已不再可交互的背景对象选择。
- 日期网格采用浅分隔线，休息日轻微区分，今天用细竖线或表头标记；不依靠颜色单独传达工时类型、完成、缺口和数据质量。
- 加载时显示与最终图表尺寸接近的占位状态；无排期、没有符合所请求范围的结果、部分数据和失败使用不同文案。当前范围清楚可见，模拟场景仅显示“模拟、未写入 TAPD”只读标识，候选比较通过对话进行。

#### 原生宿主验收

在真实 Codex 对话区及侧栏分别核对浅／深色、常规及窄宽度、任务／工时模式、内容密集时的滚动、悬浮／键盘／点击状态、项目编辑和保存。按真实截图评审视觉密度、图表占比与可读性，记录与本方案的差异后调整；本节数值是设计起点，不以本文示意图代替真实宿主验收。

## Test Plan

| 范围 | 验收标准 |
| --- | --- |
| 定向配置 | 对话打开项目、成员、分组、令牌、工时、日历及写入范围时，目标表单可操作，其他类型表单和导航不出现在卡片；无目标时分类入口可到达全部配置 |
| 保存与可靠性 | 单组保存不覆盖其他配置；空草稿、保存失败、重读、多个卡片修订冲突、同步／查找／刷新前存在草稿均有明确处理，重开后正确恢复 |
| 令牌引导 | 无令牌只打开连接配置；不向聊天回显令牌；保存后初始化成功、部分失败和原读取继续的行为分别验证 |
| 对话到图表 | 明确的日期、人员、项目和默认本月／默认组均正确映射；直接展示结果，不再要求重复输入；范围和来源时间可核对 |
| 图层及详情 | 两模式前后层、透明度、点击／悬浮／键盘焦点正确；详情数据与同一 analysisId 结构化结果一致；未排期实际工时仍显示 |
| 范围与规模 | 卡片无筛选入口，人员、项目、日期由对话确定；结果超过 20 名成员、200 项任务仍完整展示或明确数据缺口；不同范围和项目工时口径明确，过期响应不能覆盖新结果 |
| 模拟及导出 | 模拟卡片显示只读标识，不提供候选切换或前后对比控件；通过对话查看指定候选或比较；模拟不写 TAPD；对话导出范围说明准确，不将基线文件作为模拟 |
| 异常与可访问性 | 加载、空结果、部分数据、权限失败、快照／模拟过期、长名称、窄容器、浅／深主题、键盘与屏幕阅读器均能理解并操作 |
| 宿主与交付 | 在真实 Codex 对话区和侧栏分别验证布局、保存重开、两模式及详情，并确认卡片没有筛选入口；组件／协议测试、浏览器 SDK 和原生宿主分别记录，不能用截图或单元测试代替原生交互验收 |

## Assumptions

- 本方案中设置分类入口和默认卡片内容为设计建议，待用户确认后落地。明确请求某一配置时，只渲染目标内容；甘特图不提供筛选入口，操作区仅保留模式切换。
- 甘特图保留任务／工时双层模式以及前景对象的点击、悬浮和详情；不提供筛选入口。“每日工时”“风险”独立页签及卡片内导出入口移出界面，但 MCP 工具继续保留。
- 未指定时间的“打开甘特图”沿用当前业务时区的本月和默认团队；如果希望改为本周，可在实施前调整。
- 人员、项目、日期范围均通过对话指定；可复用已覆盖的快照或重新查询。现有完整分析导出的范围明确告知，不默认实现新的指定范围导出格式。
- 不改动工时规则、TAPD 写入语义、已有任务数据或 skills；本轮不实现拖拽修改排期，也不改变紧急需求只模拟的约定。
- 本次只提供分析与方案，未执行构建、测试或 Codex 原生交互验收。
