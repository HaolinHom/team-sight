# TeamSight MCP 能力对照与补齐实施方案

## Summary

依据用户确认的《TeamSight MCP 场景与能力职责梳理》，补齐配置、取数、计算、任务操作与 Apps 展示。沿用当前工作树的 P1b 基础，不覆盖既有未提交修改。MCP 提供数据和计算；需求理解、拆解方法、估时方法、报告模板、风险判断与场景流程留给后续 skills。

已具备配置 Apps/凭据库、日工时/日历/请假、TAPD 基础查询、独立实际及累计工时取数、单项任务写入/幂等/读回、快照/作业/导出。需要补齐身份和分组、项目自动同步、场景上下文、新工时口径、严格容量、协作约束、候选排期、紧急模拟、批次恢复、双层甘特和运行交付。旧报告不能代替本轮验证。

## Implementation Plan

### M1 配置、当前用户及成员范围

扩展配置 v5：当前用户、项目别名和顺序、成员启停和顺序、多分组及唯一默认组。令牌保存后自动获取身份与项目，新增项目默认全部启用，再次同步保留本地偏好；不扩大写授权。当前用户用用户信息与目录完整账号匹配，不混淆内部 ID 与工号。成员先查本地再查 TAPD，唯一匹配后只保存身份，不入默认组；歧义返回候选。分组支持测试标记。增加 teamsight_get_config/update_config/sync_projects/resolve_members，凭据仍仅由 Apps 填写，配置共用修订校验。缺配置引导设置，初始化成功反馈状态并支持继续原读取。

### M2 基础接口与场景上下文

解析现用需求/任务/缺陷 TAPD 链接；查询补齐负责人、需求及日期过滤，专用与通用入口使用同一契约。新增 teamsight_get_requirement_context/get_work_context，聚合正文、任务、负责人、估时、排期、关联对象、材料与期间活动，区分当前状态与期间事件。补齐默认组外协作与测试对象。材料/附件/历史逐项登记支持与权限缺口，不把失败当空。分页按接口配置；结果含范围、业务日期、来源、完整性和引用。

### M3 工时与容量

MCP 缺预估有效值为0且保留原始缺失；缺任一日期为未排期，实际仍按填报人与日期统计。剩余=max(预估-截至计算日累计实际,0)。过去只看实际，当天未来看实际+剩余分配，并包含当天不足。输出目标、实际、分配、差额、贡献及未安排量。容量=max(有效目标-实际-其他预计占用,0)；重排释放目标任务原预计，不释放实际。超负荷如实展示，严格排期不沿用统计器末日及休息日无上限兜底。失败和截断保持未知。新 rulesVersion，旧 Tauri 默认和旧分析保留。

### M4 普通排期与紧急模拟

新增 teamsight_plan_schedule/simulate_urgent，共用纯 TypeScript 确定性枚举回溯，最多50000状态。支持顺排、联调锚点倒排；硬约束为容量、日历、请假、日期窗口、deadline与依赖。每次刷新相关 TAPD，覆盖所有启用项目。默认节点前一工作日完成，明确时可同日。提供完整连续优先与尽早完成候选，比较间断、拆分、完成时间、同需求跨度及锚点距离；同需求任务可间隔。

紧急提供单人直接、移动已有、多人的模式。任务名含测试或负责人被分组/当前输入认定为测试，即识别为测试任务。研发移动以同需求最早完整测试排期为边界，无测试排期仍校验deadline和其他约束。仅移动未来剩余，默认保留原负责人、测试与固定节点。多人拆分及估时由Agent输入。全部模拟不写TAPD。搜索区分可行、确定冲突、未完成，预算耗尽不能当无解。

### M5 批量任务创建、补排期及恢复

新增 teamsight_write_tasks/get_task_batch。仅拆解创建关联需求、无日期任务；带排期创建；补排期更新原任务。默认当前用户。写前刷新容量、依赖、摘要，过期返回变化与重算依据。每项返回状态、实际字段和链接。稳定批次与条目标识复用回执：成功跳过、明确失败安全续办、未知先核对不重发。部分成功不删除或自动回滚。批次从回执恢复，不保存排期计划，不宣称远端事务或原子CAS。

### M6 配置与双层甘特 Apps

配置完整管理项目、成员、组和工时。默认任务前景+工时淡化背景，工时优先交换层级与交互。背景禁点击、悬浮和焦点。任务详情含需求/负责人/状态/工时/链接；每日工时详情含实际/预计/目标/差额/贡献。成员/项目/日期筛选覆盖完整结果，未排期实际仍展示。模拟对比前后，不拖拽或直接改排期。Agent与图同一结果；宿主支持时反馈选择上下文。模拟只用进程内临时缓存，过期/重启重算。

### M7 兼容及交付

配置v4到v5，旧成员入身份目录及默认组保留范围，全新默认组为空。SQLite沿用现有表，通过设置和回执JSON扩展，不新增依赖或计划表。保留原工具、回执、旧分析和资源。更新运行包版本与源码哈希，修正P0遗留。macOS arm64/Windows x64，外部Node22；服务、凭据、数据库、MCP和原生Codex交互分别验收，Windows无实机不能标通过。

## Test Plan

验证令牌初始化、当前用户、同步偏好、成员歧义、多组去重、新成员不入组、旧成员迁移；链接和材料权限；过去/当天/未来、缺预估/日期、独立花费、跨窗、多负责人、超估、日历请假；跨项目容量及重排不重复扣减；4h+4h和2h+6h可分周一周三，8h偏好完整连续、顺倒排和同日；三类紧急模拟/两种测试识别/最早测试且POST=0；普通批次/重复/部分/重启/未知/过期；双层模式与完整筛选；失败截断和预算不转为空或无解；包级及旧App回归、构建、真实Codex和Windows分别记录。真实写入仅专用验证项目、可识别任务，异常使用隔离传输。

## Assumptions

协作关系、节点与每日分配不新增跨会话持久化，每次从TAPD和当次对话重建；旧聊天特殊约定需要再提供。每日分配随事实变化。缺普通窗口默认未来90自然日，倒排节点前90日不早于计算日，显式最多366日。最终估时不乘1.5。Linux、DeepSeek Harness、skills及旧App退役不在范围。
