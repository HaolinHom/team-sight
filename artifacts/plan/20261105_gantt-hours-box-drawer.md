# 甘特图工时盒子与详情交互优化实施方案

## Summary

按用户确认的方案优化 MCP Apps 甘特图。工时盒子对应单日关联任务区域，详情通过右侧抽屉展示，任务支持简讯提示。保持工时算法、TAPD 数据、成员顺序与任务排序不变。

## Implementation Plan

- 每成员每天一个盒子，限定当天日期列，从第一条到最后一条关联任务行；关联取当天排期和工时贡献的并集，中间无关任务行不拆段。几何复用布局结果，不再用柱高表达小时数。
- 无排期但有贡献的任务保留名称行，不虚构任务条；无法匹配的贡献放入成员汇总占位行并保留来源标识。无关联任务的日期在成员标题行显示。
- 显示总小时数；达标绿色、过去不足红色、当天及未来不足橙色，无法判断灰色未知；按 analysisDate 判断日期，目标为零不标不足。
- 任务优先时任务不透明置顶，工时盒子浅色半透明；工时优先时边框、侧边状态带和小时数标签不透明置顶，内部透明，任务淡化。仅前景层可交互，更新图例。
- 共用右侧固定抽屉，宽 400px，540px 以下全宽，遮罩、关闭按钮、Escape、焦点约束与恢复、独立滚动及减少动态效果。保留图表滚动位置，切换模式或数据关闭旧详情。
- 保留任务详情字段与外链；工时详情展示状态、数值、未知原因与关联任务，区分排期和贡献。
- 任务优先悬浮约 200ms 或键盘聚焦显示任务名、项目、负责人、状态、排期、预估；边界定位、不被图表裁剪，离开、滚动或打开抽屉时关闭。
- 纯展示模型放在 MCP UI 内，以项目、类型和任务 ID 关联。复用现有分页和选择事件，不新增服务接口。

## Test Plan

- 几何：单日三任务、非连续任务行、跨日、多负责人、无排期贡献、未知来源、无任务、日期裁剪。
- 状态：过去不足、未来不足、达标、零目标、未知，模式不影响数据。
- 交互：优先层点击/键盘、背景不可交互、悬浮时序与边界、抽屉焦点及关闭、滚动位置、新数据清理。
- MCP UI 测试和构建、隔离宿主明暗/窄屏/长列表验证，尽可能复查团队十月场景。Codex 原生 Apps 未能实测的行为单独记录。

## Assumptions

仅修改 MCP Apps 展示，不修改旧 Tauri 界面、工时规则、配置或 TAPD。保留现有主题。原生宿主与隔离浏览器验收分别记录。
