# 甘特图工时关联任务与虚拟排期方案

> 2026-11-07 目录整理标注：历史实施背景：本方案对应原版本，因现行知识所引报告需要其背景而保留，已不作为待执行方案。旧配置、源码路径和阶段状态可能已退役；当前规则见[正式知识](../../knowledge/index.yaml)与[0.3.0 说明](../../docs/TeamSight-MCP-能力与使用说明.md)。

## 排查结论

洪浩林 10/15 的三个排期任务合计 8h，另有缺陷 0.5h；10/19 的官网任务 1h、两个缺陷 6h 和 1h。缺陷都有真实排期，但当前负责人已流转，成员快照漏取工作项资料。林曈「下图-回收站功能」无开始及结束日期，10/9、10/10 各贡献 4h。当前工时盒子覆盖排期与贡献行并集，缺失资料汇总到底部占位行造成延伸。

## 展示规则

- 无有效排期（缺任一日期或倒置）：按成员在完整分析范围内首末正数实际花费日生成连续虚拟条，空档连起来。
- 有真实排期但负责人变更：在贡献者分组下仅按花费日分别补块。
- 当前负责人保留真实排期，排期外花费日分别补块。
- 同成员同工作项一行，按展示开始日期排序；项目颜色、虚线边框和「按工时补充」标识。
- 悬浮及详情区分真实排期、虚拟区间、当前负责人、填报成员与每日实际工时；区间覆盖不代表每天投入。
- 林曈示例为 10/9–10/10；洪浩林缺陷在相应投入日具名显示。

## 实现与接口

- 现有工时计算后，按项目＋类型＋ID 去重补查所选成员、当前分析范围内正数实际工时缺失的工作项，沿用并发上限和取消机制。
- TeamAnalysis 增加可选关联资料，仅供展示，不进入计算任务集合。
- read_analysis 合并展示资料并附成员展示区间，沿用任务分页；过滤考虑负责人、贡献者和真实／虚拟区间。区间先依据完整分析生成，再裁剪视图及导出。
- 共享转换供 MCP 与 SVG、PNG、HTML 甘特图导出使用。工时盒子继续覆盖关联行，统计及状态规则保持。
- 补查失败保留独立类型／ID／投入日期任务块并提示；不合并占位行，不改变已知工时。
- 旧分析只读兼容，不补查或改写；缺资料用 ID。新建十月分析进行具名验收。

## 验证与验收

- 固定样例洪浩林 10/15=8.5h、10/19=8h；林曈 10/9=8h、10/10=4h，统计一致。
- 覆盖缺双日期、单边日期、倒置、间隔日、流转、多人贡献、排期外工时、跨项目／类型同 ID。
- 验证补查失败、去重、过滤、200 条分页、缩窄视图及导出跨页。
- 隔离浏览器检查双模式、虚拟标识、悬浮、抽屉、键盘、明暗主题；检查三种导出。
- MCP 构建及核心、服务端、UI 测试；真实十月新分析核对问题日期。

## 假设与边界

虚拟排期只展示，不写 TAPD、不改变真实日期、不参与排期计算及模拟。仅用分析范围内的实际工时。不改独立 Tauri 桌面和工时报表格式。
