# 甘特图空任务行修复及 MCP 0.2.6 更新方案

## Summary

根因：共享展示层为负责人包含该成员、无有效排期且该成员无实际工时的任务保留名称行，与完成状态无关。当前十月快照洪浩林有 15 个任务命中，包括“【紧急优化】官网性能紧急优化”。

## Implementation Plan

- 按成员＋任务仅保留与查看区间相交的真实排期或实际工时补充条，取消仅凭负责人保留名称行。无有效排期时，仅依据该成员在完整分析区间内正数、有限实际工时生成首末投入日连续虚拟条。
- 筛选和布局忽略旧无排期名称行标记，保留字段读取兼容；过滤先于计数和分页。任务／工时模式及 SVG、PNG、HTML 导出规则一致。
- 不改变原始任务、工时、待安排量或风险计算。有效排期无工时仍展示；已完成但有排期或实际投入仍展示。
- 增量修改现有工作区，保留已有 0.2.5 改动。服务与分析 UI 升级至 0.2.6，新分析资源保留旧地址兼容。
- 打包 macOS arm64，核验哈希、doctor 和隔离 MCP 验证；停止 LaunchAgent 后备份数据与启动配置，使用原数据、端口和凭据切换新版本，失败恢复旧启动配置。

## Test Plan

- 覆盖无排期无工时、已完成多负责人本人无工时、仅其他成员有工时、单边／倒置日期、零值／非法工时、有效排期无工时。
- 验证虚拟条保留，缩窄日期、成员筛选、分页与导出一致，旧标记不重新引入空行。
- 同一十月快照洪浩林工作项 55→40，15 个空任务消失；其他有效任务、每日工时不变。
- MCP 构建、core／TAPD／server／UI 测试；验证两种模式、名称列、工时盒子及详情关联。
- 升级后检查 0.2.6 状态、配置和历史完整性，并在当前聊天重新打开十月分析。

## Assumptions

- 无工时按选定分析区间判断，不额外查询全历史；沿用实际工时补充展示规则。
- 仅更新本机 MCP，不修改 TAPD，不提交／推送 Git，不更新独立 Tauri 看板或其他平台包。
