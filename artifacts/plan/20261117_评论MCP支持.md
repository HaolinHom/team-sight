# 需求、任务、缺陷评论 MCP 支持方案

## Summary

仅通过对话调用 MCP，支持需求、任务、缺陷的评论读取、新增和回复。附件保持只读：查询已有附件、获取下载链接及识别评论中的图片和文件引用。不支持附件上传，不新增 MCP Apps 评论表单。

## Implementation Plan

- 新增 tapd_list_comments、tapd_add_comment，并纳入通用操作目录。
- 对外统一使用 story/task/bug，映射为 TAPD 的 stories/tasks/bug；读取缺陷评论时包含 bug_remark。
- 评论读取支持分页，返回 ID、作者、时间、正文及回复关系；分页失败或关联异常明确标记不完整。
- 新增评论接收项目、工作项类型和 ID、正文、可选回复目标及幂等键。正文按纯文本转义并保留换行。
- 评论人使用当前令牌对应的完整账号；回复前核实目标评论属于同一项目和工作项，服务端确定根评论及回复 ID。
- 复用 attachments.list、attachments.download_link；保留评论图片和附件引用，临时下载链接按需获取，不作为永久地址保存，内容由调用方按需读取。
- 新增独立的发表评论权限，旧配置默认关闭，在现有连接设置中提供选项。沿用已启用且可访问的项目范围，不依赖工作项字段修改权限。
- 发布前校验目标、身份、回复归属及权限，发布后读取核实。扩展持久化回执，兼容已有工作项回执；重复幂等键复用结果，未知结果先查询核实，不自动重发。返回评论 ID、工作项链接和回执。

## Test Plan

- 覆盖三类工作项的读取、新增、回复，以及缺陷流转评论读取。
- 验证分页、中文、多行、特殊字符、作者身份、权限关闭及跨工作项回复拒绝。
- 验证重复调用、发布超时、读取核实失败、服务重启，避免重复发表评论。
- 回归附件列表、下载链接和已有评论引用；权限失败不解释为没有附件。
- 执行相关接口、业务回归和构建；在明确指定的专用测试工作项上真实联调，分别记录已验收及未验收范围。

## Assumptions

仅使用现有 Bearer 令牌。不包含附件上传、评论编辑/删除、@通知、评论表单或线上发布。未指定专用测试工作项时，不向业务工作项写入测试评论，真实写入验收明确列为未验收。

用户在实施期间指定可在需求 `https://www.tapd.cn/tapd_fe/62119705/story/detail/1162119705001212279` 发布测试评论。真实写入仅限该需求；任务、缺陷未获得专用测试对象。
