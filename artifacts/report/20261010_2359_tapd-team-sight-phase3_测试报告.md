# TeamSight 阶段3 测试报告

## Summary

- 测试对象：阶段3 交付物（顶部筛选条、自定义时间范围、项目/成员/状态多选、已完成任务视觉弱化、预估工时展示）。
- 测试方式：前端单元测试、类型检查与生产构建、fixture 模式浏览器视觉与交互实测、桌面端端到端加载验证、拉取入口代码级核对。
- 结论：全部通过；筛选交互与完成态视觉在浏览器实测确认；桌面端加载行为与阶段2 一致，无额外请求。

## Results

### 1. 单元测试（`pnpm test`）

- 结果：14 个测试文件、**123 个用例全部通过**（阶段2 为 99 个，本轮新增 24 个）。
- 新增覆盖：
  - 筛选：默认全选（`null`）语义、项目过滤、状态按「来源类型 + 原值」组合键过滤（同名状态不互相误伤）、空数组 = 全部取消、状态选项去重计数与排序、空集合。
  - 时间范围：合法区间、非法日期、起晚于止（不自动交换且不返回范围）、超 366 天截断、超 92 天数据量提示、常量边界。
  - 完成态：`done/closed/resolved/rejected` 命中（忽略大小写与空格）、`open/progressing/已完成/空`均为未完成。
  - 成员：`selectMembersByKeys` 的 null/子集/空数组语义、`createMemberResolution` 的隐藏计数，取消勾选成员后其任务不再产生分组。
  - 展示字段：`effort` 映射（有值保留原字符串、null 不臆造为 0）、tooltip 新增工时行与完成态标注（中文自定义状态不误判）。
  - 看板状态：区分「无数据」与「筛选后为空」两种文案。
  - fixture 契约：固定验收数据同时包含已完成/未完成状态与有工时/无工时样本。

### 2. 类型检查与生产构建（`pnpm build`）

- 结果：`vue-tsc --noEmit` 与 `vite build` 通过。看板页 26.39 kB（gzip 9.90 kB）。

### 3. 视觉与交互验收（`pnpm dev` + `VITE_BOARD_FIXTURE=1`）

| 验收项 | 结果 |
| --- | --- |
| 筛选条渲染 | 通过：时间范围（两个日期输入 + 上一月/本月/下一月）、项目/成员/状态三个下拉带「全部 N」徽标 |
| 多选交互 | 通过：取消勾选李四后其分组整组消失（仅剩王五、张三），徽标变为「已选 2/3」 |
| 状态筛选 | 通过：取消勾选「任务 done」后浅色任务条消失，徽标变为「已选 3/4」，状态选项按「任务/缺陷」分组且带条数 |
| 已完成任务变浅 | 通过：`done`/`closed` 状态的任务条明显更浅（如「埋点补全」「修复列表分页异常」），标签文字转深色保持可读 |
| 预估工时展示 | 通过：tooltip 与底部信息条均显示「预估工时：2」（原值不加单位）；无工时任务不显示该行 |
| 筛选后空成员分组不出现 | 通过 |

状态选项实测（fixture）：`任务 open 8 条 / 任务 done 1 条 / 缺陷 open 3 条 / 缺陷 closed 1 条`，印证动态枚举与按来源分组。

### 4. 端到端与拉取行为

- 桌面端 `pnpm tauri:dev` 重启后自动加载：`/workspaces/users` 8 次 + 总计 40 次 TAPD 请求（8 个已启用项目 × 每项目 5 次），与阶段2 基线一致，无额外或重复加载。
- 拉取入口代码级核对：`schedule.refresh()` 仅由「挂载时」「时间范围变化」「点击刷新」三处触发；项目/成员/状态筛选只改动筛选状态并触发本地计算，不会调用刷新。

## Issues

- 本轮未发现缺陷。
- 已确认的偏离（用户决定）：
  1. **阶段3 第9 项「未排期任务辅助展示」未实现**，单边日期任务也不进看板。原因：实测窗口查询天然不返回缺日期任务，需用 `due=null`/`begin=null` 单独拉取，单项目量级可达 2260 条，且多人查询语法不可用（逐人查询请求数近百），成本与收益不匹配。
  2. **阶段3 第6 项「任务详情展示」以 tooltip + 底部信息条形态交付**，未新增独立详情面板；字段覆盖名称/项目/负责人/状态/开始/截止/优先级/预估工时 与「打开 TAPD」链接。
- 交互体验优化（hover 联动高亮、点击空白取消选中、自动滚动到今日、键盘可达）本轮未做；用户本轮指定的是「已完成任务颜色变浅」，已交付。

## Not Tested

- 桌面窗口内的筛选点击（下拉、日期选择器）：开发二进制无 bundle id，自动化工具无法绑定窗口，需人工点一次确认；同一套交互已在浏览器 fixture 模式实测。
- 真实数据下的状态选项人工核对：已由单元测试覆盖枚举逻辑，浏览器实测覆盖分组与计数渲染；桌面端的真实状态值（open/progressing/done）未在界面上逐一点验。
- 大范围（>92 天）拉取的性能表现与阶段4 的虚拟滚动评估。
