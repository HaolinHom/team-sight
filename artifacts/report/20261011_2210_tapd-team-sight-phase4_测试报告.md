### 2. 异常与边界加固

- 修复 `useCredentials.refresh()` 未捕获异常：凭据文件损坏时不再冒到 `onMounted` 形成未处理拒绝，改为置「未配置」并在看板显示「读取凭据失败：…」（有组件测试覆盖，且断言此时不会发起 TAPD 请求）。
- 错误提示按原因去重：同一凭据/权限问题不再按项目重复刷屏。
- 新增边界测试：单日时间范围（起=止）、跨年范围、超长标题截断、异常 `effort` 原值透传、配置/凭据损坏回退。

### 3. 性能验证（结论：不引入虚拟滚动）

压测数据：`VITE_BOARD_FIXTURE=stress`，2000 条任务 / 8 名成员 / 10 个项目，全部落在当前自然月（默认视图即渲染全量）。

| 指标 | 实测 |
| --- | --- |
| 单元层：`computeLayout` 处理 2000 条 | 通过（阈值 1500ms 断言，实际远低于阈值） |
| 首屏渲染（全部 2000 行 + 2000 任务条出现） | **≈275ms**（含工控轮询的 IPC 往返开销；单次同步渲染完成） |
| DOM 规模 | 2000 任务行 + 2000 任务条 + 8 成员分组；时间轴内容高度 68,284px |
| 滚动响应 | 10 次滚轮翻页共 411ms（平均 ≈41ms/次，含 IPC 往返） |
| 滚动后对齐 | 截图核对：表头吸顶、左列与任务条同步、当日标记位置正确 |

判定：首屏远低于 1.5s 预算、滚动响应正常，**本轮不引入虚拟滚动**；若后续真实数据量级显著变大（例如单视图数千行且开启多项目全量加载），再按同一方法复测。

### 4. 令牌泄漏审计

新增 `pnpm verify:secrets`（`scripts/check-secrets.mjs`）：读取 `.env.local` 的令牌，扫描 `dist/`、`src-tauri/target/release/`、`README.md`、`docs/`、`artifacts/`。

- 打包前：扫描 24 个文件 → 未发现泄漏。
- 打包后（含 `.app` 与 `.dmg`）：扫描 **3191 个文件** → 未发现泄漏。
- 设计约束核对：release 构建不读取 `.env.local`（`cfg(debug_assertions)` 限制），只认应用内凭据文件与环境变量；桌面端不写前端存储（localStorage 仅浏览器开发模式使用）。

### 5. macOS 打包验证

`pnpm tauri:build`（`bundle.active=true`、`targets=["app","dmg"]`）产出：

- `src-tauri/target/release/bundle/macos/TeamSight.app`（12.72 MiB）
- `src-tauri/target/release/bundle/dmg/TeamSight_0.1.0_aarch64.dmg`（3.59 MiB）

验证结果：

- 启动 `.app` → 进程正常、注册为前台应用（bundleID `com.haolinhom.team-sight`、Version 0.1.0、ARM64）、窗口标题正确。
- 窗口内容来自内嵌资源（`tauri://localhost#/board`），界面读到真实配置：已启用项目 8、展示成员 6、任务行 283、未命中展示成员 234 条、最后刷新时间正确，成员分组与真实 TAPD 任务标题正常展示。
- `.dmg` 可挂载（内含 `TeamSight.app` 与 `Applications` 软链）并可正常卸载。
- 产物已通过令牌泄漏扫描。
