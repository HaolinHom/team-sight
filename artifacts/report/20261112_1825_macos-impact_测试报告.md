# Windows 改动对 macOS 的影响检查报告

## Summary

对当前工作区相对 HEAD 的改动进行静态对照检查。当前环境为 Windows 10 x64，本报告不代表 macOS 实机回归通过。

结论：未发现会破坏 macOS 的改动；业务运行代码、macOS 启动与安装逻辑未变。共用打包和验收脚本存在调整，仍需在 macOS 上完成最终回归。

## Results

- `apps`、`packages/core`、`packages/tapd/src`、TAPD 包配置、依赖锁文件和工作区配置均无已跟踪改动。
- macOS 安装器原有文件及 `scripts/build-installer.mjs`、`scripts/install.sh`、`scripts/package-mcp-lib.mjs` 无改动；原有 build、test 和 macOS 安装命令未改变。
- `scripts/package-mcp.mjs` 仅向源码哈希清单加入 Windows 管理和验收文件；未改变 macOS 文件复制、原生模块、运行时和归档逻辑。新增文件均存在，提交时须一并包含；重新打包的源码哈希会变化。
- 共用验收脚本保留 darwin arm64 原生验收分支，新增可选单平台清单。Windows 原生验收受 win32/x64 条件限制；Windows 模块在移除 ProgramFiles、SystemRoot 环境变量后仍可导入，导入阶段不会调用 PowerShell。
- macOS 路径专属用例只在 darwin 执行；链接拒绝测试在 Windows 使用 junction，在 macOS 保留文件符号链接。新增配置助手测试使用 Node 和临时目录，静态检查未发现 macOS 必需的 Windows 环境依赖。
- `packages/tapd/node_modules/@teamsight/core` 在 Git 中显示删除；本地实际为指向 `packages/core` 的 Windows junction。它属于安装生成的依赖链接，其他环境应通过 `pnpm install --frozen-lockfile` 重建，不能当作业务源码删除。
- `git diff --check` 通过。

## Issues

未发现 macOS 兼容缺陷。上述依赖链接的 Git 状态需要在整理提交时注意，不能误认为业务模块已删除。

## Not Tested

- 未在 macOS 执行依赖安装、构建、完整测试、doctor、双发行包原生验收和安装器回归；当前电脑为 Windows，静态审查不能替代这些验证。
- 本次 Windows 安装、计划任务和本机 Codex 配置操作不会更新其他电脑上已安装的 macOS 服务；未来分发新版本仍应先完成 macOS 回归。
