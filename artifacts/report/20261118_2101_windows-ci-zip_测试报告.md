# Windows CI 发行 ZIP 打包修复测试报告

## Summary

用户提供的 Windows Actions 日志中，依赖安装和 `mcp:build` 完成，首次明确错误发生在 `mcp:package win32-x64` 创建发行 ZIP 的 `tar` 调用。原错误只保留了命令名，无法确定该 runner 实际执行的二进制、退出状态或更具体的失败原因。

## Results

- Windows 主机固定使用系统 `tar.exe`；从暂存目录用相对路径显式创建 ZIP。命令失败时保留启动错误、退出码或信号。macOS `.tar.gz` 的创建参数不变。
- macOS arm64／Node.js 22.23.4：23 项脚本测试通过；新增往返用例核对 ZIP 与 gzip 文件签名，以及含空格暂存目录中的归档根目录和解包内容。Windows 构建也会运行这项回归。
- 隔离检出目录中按平台分别生成四份归档及 SHA-256 清单。两份 Windows ZIP 通过包内哈希、PE x64 和公共内容一致性检查；macOS 双包通过原生运行验证。两平台共四条 Pages 安装脚本生成通过，macOS 两条另通过 `sh -n`。
- `git diff --check` 通过。

## Issues

- 本地验证使用聚合清单去跑单平台校验时找不到平台清单，改按发布工作流逐平台生成。macOS 原生校验初跑被 `/tmp` 和 `/private/tmp` 路径比较拦下，使用真实路径后复验通过；两项均未修改验收逻辑。

## Not Tested

- 未在 Windows runner 重现原始失败或实跑修复后的 CI；未执行正式发布或部署。Windows ZIP 的本地验证不等价于 Windows 原生验收。
