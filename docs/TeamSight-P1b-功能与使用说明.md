# TeamSight 截至 P1b 的功能与使用说明

更新日期：2026-10-29。依据[技术方案 v1.2](../artifacts/plan/20261027_2341_teamsight-server-mcp-apps-technical-plan.md)、[分阶段执行方案](../artifacts/plan/20261028_teamsight-v1.2-phased-implementation.md)、当前源码及[验收报告](../artifacts/report/20261028_teamsight-p1b_测试报告.md)整理。

当前可通过 **本地 TeamSight Server + Codex MCP 工具 + 会话内 Apps 卡片**使用业务功能。本文列出 P0、P1a、P1b 已实现的能力和操作方法；P1c 的正式发行、Windows 实机验收、完整迁移和宿主定时工作流尚未交付。

## 1. 现在能用什么

| 功能 | 如何使用 | 当前边界 |
| --- | --- | --- |
| 服务状态与诊断 | 对话调用 `teamsight_status`；本机 CLI 使用 `status`、`doctor` | 需要先启动本地 HTTP 服务，MCP 地址配置本身不会启动它 |
| 会话内设置 | 对 Codex 说“打开 TeamSight 设置”，在卡片中编辑并保存 | 使用正式 `teamsight_open_settings`，旧 `teamsight_probe_*` 是 P0 验证入口 |
| 团队与分析范围 | 配置团队名、业务时区、项目 ID/名称/颜色/启用状态、成员工号和姓名 | 时区支持 `Asia/Shanghai`、`UTC`；成员按配置列表顺序显示 |
| 工时与请假规则 | 设置每日目标、成员某日请假小时、各项目 task/bug 结束状态 | 请假减少目标，不创建 TAPD 请假单；工作日目标为 `max(每日目标 − 请假小时, 0)` |
| 中国节假日与调休 | 设置卡片启用中国日历；已缓存年份可点击刷新 | 缺失年份由分析时自动获取；失败会显示限制，不能据此确定工时不足 |
| 旧 JSON 配置导入 | 在设置卡片粘贴旧 App 的 `settings.json`，点击“导入旧配置” | 导入会替换当前业务配置；凭据字段忽略，TAPD Token 需单独填写；完整迁移验收仍属 P1c |
| 项目、成员、字段与状态查询 | 列出可见项目，再读取指定项目的需求/任务元数据 | 设置卡片手动添加项目和成员；元数据可由 Agent 查询，没有旧 App 的完整候选选择界面 |
| 需求、任务、缺陷查询 | 对话搜索或按 ID 读取；也可用设置卡片底部的只读查询 | 支持 `story/task/bug`；搜索按页返回，不能把第一页当全量 |
| 创建需求和任务 | 先开放写入范围，再对 Codex 描述项目、类型、标题和字段 | 支持 `story/task`，不支持缺陷写入；需要 TAPD 实际写权限 |
| 修改需求和任务 | 先读当前对象及摘要，再提交字段修改 | 仅允许已开放且对象元数据支持的字段；摘要冲突需重新读取 |
| 写入回执与核对 | 查询 `operationId`；未知结果执行只读核对 | 本地幂等减少重复请求，不保证 TAPD 远端恰好执行一次 |
| 基础排期读取 | 指定开始/结束日期读取启用项目的 task/bug 排期 | 日期窗口查询不包含缺日期工作项；检查缺排期应使用完整分析 |
| 复合排期与工时分析 | 对话提交日期范围，或打开分析卡片点击“开始分析” | 默认分析启用项目和配置成员；需求不参与工时汇总 |
| 甘特图、每日工时与风险卡片 | 在“甘特图 / 每日工时 / 风险与依据”间切换 | 支持成员筛选、工时贡献明细、风险依据、工作项链接及分批加载 |
| 静态图表与报告 | 卡片底部导出，或让 Codex 对指定分析生成文件 | PNG、SVG、CSV、Markdown、HTML、JSON；图表和报告共用同一分析 |
| 较长分析作业 | 返回作业 ID 后查询进度；卡片自动轮询并提供取消 | 取消面向分析读取，不能用于撤销 TAPD 写入；重启中断的分析需重新开始 |

上述功能已有实现与验证记录，但验证层次有区别：macOS arm64 已完成构建、自动化、指定项目真实需求/任务读写及 SDK 浏览器分析验证；2026-10-29 用户已确认 Codex 原生分析卡片可见。原生卡片的完整交互、宿主文件呈现和 P1b 设置新增表单保存往返，最近报告仍标为待人工验收，详见[补充报告](../artifacts/report/20261029_teamsight-p1b-native-host_测试报告.md)。

## 2. 开始使用

### 2.1 启动并连接服务

当前是源码运行方式。建议使用已验收的 **Node.js 22.23.4 / pnpm 10.12.4**；运行时校验门槛为 Node.js 22.14.0+、小于 23，Node-API 10。当前机器已安装该 Node 版本，可在终端使用 `nvm use 22.23.4` 切换，然后检查版本。

首次准备源码环境，或源码有更新需要重建时，在仓库根目录执行：

```sh
cd /Users/haolin/Projects/team-sight
node --version
pnpm --version
pnpm install --frozen-lockfile
pnpm p1b:build
```

已有依赖和构建产物时，可直接启动。沿用此前 P1b 验收配置与分析：

```sh
cd /Users/haolin/Projects/team-sight
mkdir -p .local
node apps/server/dist/cli.js serve --data-dir .local/teamsight-p1b-live --port 43129 2>&1 | tee .local/teamsight-p1b-run.log
```

此命令前台运行，保留该 iTerm 会话；其他命令在另一个会话执行。2026-10-29 本次整理时，`43129` 健康检查返回 `ECONNREFUSED`，原服务未响应，以上是恢复使用所需的启动步骤。数据目录内保留此前配置、快照、分析和操作回执，不能为重试而清空。

在另一会话检查状态：

```sh
node apps/server/dist/cli.js status --data-dir .local/teamsight-p1b-live
```

Codex 需要连接 `http://127.0.0.1:43129/mcp`，并使用同一数据目录的本地 MCP 访问令牌。已有连接可直接复用；此前连接名是 `teamsight_p0_probe`，名称不代表服务仍为 P0，应以 `teamsight_status` 返回的 `phase=P1b` 为准。新建连接的配置方式见[服务说明](../apps/server/README.md#连接-codex)，其中示例端口应与实际启动端口一致。

连接后对 Codex 说：

> 检查 TeamSight 服务状态，然后打开正式 TeamSight 设置。

服务监听本机 `127.0.0.1`；需要由同机可达该服务的宿主调用。当前没有供用户直接访问的独立浏览器设置网站。

### 2.2 第一次配置

1. 打开正式设置卡片，填写团队名称、业务时区和每日目标工时。默认时区 `Asia/Shanghai`、目标 8 小时。
2. 在“TAPD 连接”填写 personal token 并点击“保存设置”。Base URL 通常保持 `https://api.tapd.cn`。Token 留空表示保留已存凭据，保存后不回显。
3. 在底部“TAPD 基础查询（只读）”点击“列出项目”，确认凭据可读取项目。这是当前可用的连接检查方法，卡片没有独立“测试连接”按钮。
4. 在“项目配置”手动添加需要分析的项目 ID、显示名称、颜色，并勾选“启用”。“列出项目”只查询，不会自动把返回项目加入配置。
5. 填写 TAPD 的“Workspace IDs”作为允许访问的项目范围；留空时采用已配置的项目 ID。启用状态决定默认分析项目，访问范围另行校验。
6. 在“成员配置”添加工号与显示姓名。可让 Codex 读取项目元数据，确认 TAPD 成员目录；分析配置使用账号末尾的工号，写入负责人则使用完整账号，两者用途不同。
7. 按需添加小时请假、项目结束状态规则，并启用中国日历。点击“保存设置”，再点“重新读取”核对结果。

设置通过当前修订号保存。看到 `REVISION_CONFLICT` 时，先记录尚未保存的修改，再“重新读取”并重新编辑，不能用旧卡片覆盖另一会话已保存的配置。刷新日历或从另一卡片修改配置，也可能使当前修订变旧。

Token 写入系统凭据库，读取仅返回是否已配置。本地 MCP 访问令牌与 TAPD Token 是两种凭据；设置卡片经宿主提交秘密，不据此承诺宿主内部日志的保密行为。

### 2.3 导入旧 App 配置

先在本机备份旧 `settings.json` 和当前有效配置，再在“旧配置导入”粘贴 JSON、点击“导入旧配置”。导入立即提交到服务，按返回的新修订显示；之后重新读取，核对项目、成员顺序、每日目标、小时请假、结束状态和日历缓存。

旧文件中的凭据字段会忽略，需在 TAPD Token 输入框单独保存。导入业务配置不等于完成旧 App 退役或凭据自动迁移；旧桌面端与服务继续使用各自的数据目录。

## 3. 日常查询怎么用

以下对话中的尖括号内容需替换为实际值。它们是使用模板，本次整理未执行任何 TAPD 写入。

| 想做的事 | 可以直接对 Codex 说 |
| --- | --- |
| 查看项目 | “列出我当前 TAPD 凭据可以访问的项目，显示名称和项目 ID。” |
| 查询成员与字段 | “读取项目 `<项目ID>` 的任务元数据，列出成员完整账号、可写字段和状态值。” |
| 搜索需求 | “在项目 `<项目ID>` 搜索标题含‘活动审批’的需求，先显示前 50 条；如果仍有后续页请注明。” |
| 读取单项 | “读取项目 `<项目ID>` 中 ID 为 `<工作项ID>` 的任务，显示负责人、日期、预估工时和状态。” |
| 只取日期窗口排期 | “读取已启用项目在 2026-10-26 至 2026-11-01 的任务和缺陷排期，说明数据是否完整。” |
| 查看完整团队分析 | “分析已配置团队 2026-10-26 至 2026-11-01 的排期与每日工时，分析日为 2026-10-29，打开分析卡片并说明风险和数据限制。” |

搜索工具支持项目、类型、关键词、状态和分页；ID 一律按字符串传递。设置卡片的搜索固定请求前 50 条，后续页由 Agent 使用工具读取；项目列表/搜索结果中的全部对象，也不自动成为分析成员覆盖范围。

## 4. 排期、工时和风险怎么用

### 4.1 生成一次分析

可让 Codex 调用 `teamsight_analyze_hours`，也可先调用 `teamsight_open_analysis` 打开空分析卡片，再填写开始日期、结束日期和分析日，点击“开始分析”。

- 开始/结束日期：要查看和导出的业务日期范围，包含首尾日期。
- 分析日：区分历史实际、当天进度与未来预计的日期；省略时按配置业务时区取当天。
- 项目/成员：默认使用启用项目和配置成员；Agent 可通过 `projectIds`、`memberIds` 明确缩小范围，所选对象仍需已配置且项目在允许范围内。
- “开始分析”：允许复用 60 秒内的完整取数缓存。“刷新数据”：强制重新取数。缓存命中保留原始来源时间。

超过两秒可能先返回 `jobId`。Agent 使用 `teamsight_get_job` 查询至完成，取得 `analysisId` 后打开卡片；卡片会自动轮询。需要停止时使用卡片“取消”或 `teamsight_cancel_job`。服务重启后作业若为 `interrupted`，重新发起分析。

一次分析保存后保持不变。`snapshotId` 标记来源快照，`analysisId` 标记计算结果；后续读风险、画图、导出报告应复用该 `analysisId`，便于核对同一批事实。修改设置或 TAPD 工作项后，重新分析才能得到新结论。

### 4.2 阅读分析卡片

1. 先看“数据完整 / 部分数据 / 取数失败”、来源时间及“范围与数据限制”。`complete` 只表示声明的覆盖范围完整。
2. “甘特图”查看成员分组和工作项日期条；缺日期对象保留标签，不会虚构日期条。
3. “每日工时”查看每名成员每天的目标、已填报实际、未来预计和差额。展开“查看 / 含待确认项”读取贡献明细；“待安排 / 未知剩余量”保留未能分配的工作项。
4. “风险与依据”查看已结束日实际不足、未来预计不足、缺有效排期、缺有效预估和未结束工作项逾期，展开“查看依据”追溯。
5. “工作项明细”查看项目、状态、日期和工时，点击“在 TAPD 中查看”跳转工作项。
6. 如果提示分批加载，点击“加载更多成员 / 工作项 / 风险”。成员筛选只作用于当前已加载的界面数据。

当前未结束日仅显示进度，不判定为已结束日工时不足。缺失、异常、截断和取数失败必须连同结论阅读，未知工时不能当作 0，也不能把空风险列表解释为完整扫描后无风险。

### 4.3 工时口径

实际工时按 TAPD 填报日期与填报人独立汇总，不只统计日期条落在当前窗口的任务。未结束任务的累计花费另行读取，用于扣减剩余量和未来分配；多人任务按既有规则分摊。需求不和子任务重复累计。

服务输出单位为小时，应先确认项目中的 TAPD 工时填写约定与之相符；当前不提供按不同项目单位自动换算。小时请假与中国日历调整工作日目标及预计安排，修改这些规则后需重新分析。

分析覆盖配置成员的 task/bug，不扫描无负责人对象；当前模型也不判断人员容量超载、交付可行性或个人绩效。没有历史快照时，不推断历史排期变化或期间完成量。

## 5. 创建和修改需求、任务怎么用

### 5.1 先开放范围

在设置卡片“TAPD 写入范围”填写允许写入的项目 ID，勾选“创建 / 修改”，填写允许字段并保存。默认/旧配置迁移不会自动开放写入；读取成功也不能证明 TAPD 实际账号有写权限。

已登记的字段为 `name`、`description`、`owner`、`begin`、`due`、`effort`、`status`、`story_id`、`iteration_id`、`workitem_type_id`。实际写入还受对象元数据限制，不是每种对象都支持全部字段。可先只开放所需字段，例如 `name, owner, begin, due, effort, story_id`。

创建前让 Agent 读取 `tapd_get_workspace_schema`：负责人使用目录中的完整账号（如 `姓名_工号`，多人用 `;` 分隔）；任务状态为已登记的 `open/progressing/done`，需求状态读取项目元数据。创建必须有标题，使用远端初始状态，不能在创建请求中指定 `status`；需要变更状态时创建成功后另行修改。

### 5.2 创建示例

> 在项目 `<项目ID>` 创建一个任务，标题为“接口联调”，负责人使用项目成员目录中 `<成员>` 的完整账号，开始日 2026-11-02，截止日 2026-11-04，预估 8 小时，关联需求 `<需求ID>`。先检查项目元数据和写入范围，再执行，并返回操作回执与读回核对结果。

Agent 调用 `tapd_create_item`，传入 `workspaceId`、`entityType=task`、`fields`、稳定的 `idempotencyKey` 和用于回执记录的 `actor`。创建需求时改用 `entityType=story`，字段按该需求类型元数据选择。

同一个写入意图保持同一幂等键和相同参数，包括 `actor`。回执 `succeeded` 并读回核对成功后，再报告创建成功及远端 ID。

### 5.3 修改示例

> 读取项目 `<项目ID>` 中任务 `<任务ID>`，将截止日调整为 2026-11-05，其余字段保持原值。使用本次读取的摘要检查冲突，执行后读回确认，并返回回执。

Agent 先调用 `tapd_get_item` 获得 `digest`，再调用 `tapd_update_item`，提交 `id`、`expectedDigest`、要修改的字段及新的稳定幂等键。出现 `ITEM_CONFLICT` 时重新读取实际对象并核对修改意图。修改摘要只能降低覆盖风险，TAPD 未提供原子条件更新保证。

### 5.4 结果未知时

写入回执可能是 `pending`、`in_flight`、`succeeded`、`failed` 或 `unknown`。请求发出后超时、断连或服务重启，不能直接认为写入失败。

1. 使用 `tapd_get_operation` 读取原 `operationId`。
2. 若为 `unknown`，使用 `tapd_verify_operation` 只读核对已知远端对象。
3. 远端 ID 不明时，先按本次独特标题/标记搜索对象，再把候选 ID 交给核对工具。
4. 核实前不换幂等键重发，不删除回执或数据目录。`IDEMPOTENCY_KEY_CONFLICT` 表示同键参数发生变化，需先查清原操作。

当前不支持删除、权限修改、缺陷创建/修改、任意 TAPD URL/字段调用，也没有批量重排和插队优化流程。

## 6. 图表和报告怎么导出

在分析卡片底部“导出完整分析”点击格式，再点击“预览”；也可直接让 Codex 操作：

> 使用刚才的同一个 analysisId，生成 PNG 甘特图、CSV 每日工时表和 Markdown 报告，读取返回的产物；同时说明来源时间和数据限制。

| 格式 | 实际内容 | 工具 |
| --- | --- | --- |
| PNG / SVG | 中文成员分组甘特图，较大范围自动分图 | `teamsight_render_gantt` |
| HTML 甘特图 | 将分图放入一个静态 HTML 文件 | `teamsight_render_gantt`，`format=html` |
| Markdown / HTML 报告 | 来源与上下文、每日工时表、当前排期、风险依据、数据限制 | `teamsight_generate_report` |
| CSV | 成员 × 日期的工时明细，含目标、实际、预计、差额、口径、状态和限制 | `teamsight_generate_report` |
| JSON | 完整分析事实、快照内容、成员每日明细、风险与上下文 | `teamsight_generate_report` |

卡片的 HTML 按钮生成的是**报告 HTML**。导出使用整个分析的成员和日期范围，不随界面成员筛选或已加载页数改变。如果只要某一成员/项目的文件，先生成该范围的新分析，再导出。

产物返回 `artifactId`、MIME、大小、SHA-256 和 `teamsight://artifacts/{id}` 资源引用。Agent 可使用 `teamsight_read_artifact` 读取图片或分段文本，文本有 `nextOffset` 时继续读取；不依赖用户提供服务端绝对文件路径。卡片对文本提供内容预览，不等于宿主已验证可执行 HTML 或自动下载文件。

静态甘特每页最多 30 天、30 个实际“成员—工作项”行，总上限 200 页并检查像素预算，超限需缩小分析范围。当前没有 PDF、XLSX 或报表模板编辑器。

## 7. 常见问题与后续阶段

| 现象 | 处理 |
| --- | --- |
| 服务未响应 / 连接拒绝 | 先用相同数据目录执行 `status`，确认 Node 版本、服务是否启动、端口与 MCP URL 是否一致 |
| 端口或实例锁冲突 | 核对已存在实例的进程身份与健康状态；不能只因有锁文件就删除或结束未知进程 |
| 服务正常但当前对话没有工具/卡片 | 检查实际连接名和 URL，在 Codex 重新连接 MCP；以原生 `teamsight_status` 成功为准 |
| `CONFIG_REQUIRED` | 打开正式设置，确认 TAPD 凭据、已启用项目及分析成员已保存 |
| `PROJECT_NOT_ALLOWED` / `WRITE_NOT_ALLOWED` | 检查 TAPD 读取范围，以及写入项目、操作、字段范围；两层要求都要满足 |
| 负责人仅填写姓名/工号被拒绝 | 读取项目成员目录，使用返回的完整 `user` 账号；有候选时先确定目标 |
| `partial` / `failed` | 阅读范围、问题和未知量；修复权限、凭据、分页或日历缺口后刷新分析 |
| 看到了旧数据或旧规则 | 确认来源时间和 `analysisId`；保存设置后重新分析，必要时点“刷新数据” |
| 需要排查本机依赖 | 执行 `node apps/server/dist/cli.js doctor`，验证 SQLite、系统凭据库及 PNG 渲染 |

确实需要停止服务时执行：

```sh
node apps/server/dist/cli.js stop --data-dir .local/teamsight-p1b-live
```

P1c 之前，以下能力不作为现成交付承诺：正式安装/发布包、Windows 实机闭环、完整配置迁移与旧 App 退役、稳定的宿主定时与无人值守工作流。P0 有过最小宿主调度验证，不等于 P1b 已交付周期日报/周报产品流程；本次也没有创建定时任务。

Deepseek Harness、Linux、更多 TAPD 对象及紧急插队/批量重排属于后续阶段。旧 Vue/Tauri App 仍可使用原有看板和工时功能，操作见[原用户手册](./用户手册.md)，其运行入口与服务形态不同。

## 8. MCP 入口速查

| 用途 | 当前正式入口 |
| --- | --- |
| 状态、设置卡片 | `teamsight_status`、`teamsight_open_settings` |
| 卡片配置读写/导入 | `teamsight_read_settings`、`teamsight_save_settings`、`teamsight_import_settings`（声明为 app 可见，常由卡片经宿主桥调用） |
| 项目与元数据 | `tapd_list_workspaces`（别名 `tapd_list_projects`）、`tapd_get_workspace_schema` |
| 工作项读取 | `tapd_search_items`、`tapd_get_item` |
| 需求/任务写入与回执 | `tapd_create_item`、`tapd_update_item`、`tapd_get_operation`、`tapd_verify_operation` |
| 固定操作目录 | `tapd_list_operations`、`tapd_describe_operation`、`tapd_call_operation`；包括已登记的工作项查询/计数、工时查询/计数与需求/任务读写 |
| 排期与分析 | `teamsight_get_schedule`、`teamsight_analyze_hours`、`teamsight_start_analysis` |
| 作业与日历 | `teamsight_get_job`、`teamsight_cancel_job`、`teamsight_refresh_calendar` |
| 分析界面及依据 | `teamsight_open_analysis`、`teamsight_read_analysis`、`teamsight_check_risks` |
| 图表、报告与文件 | `teamsight_render_gantt`、`teamsight_generate_report`、`teamsight_read_artifact` |

固定操作目录仍受相同权限、字段、身份与幂等校验，不能用通用入口绕过限制。表中是服务端入口清单，宿主是否向当前对话模型展示各工具，以实际发现结果为准。

需要单独查询原始工时或对象计数时，可说：“列出 TeamSight 已登记的 TAPD 操作，查看 `timesheets.search` 的参数契约，然后读取项目 `<项目ID>` 在 2026-10-26 至 2026-10-29 的 task/bug 工时记录。”Agent 先发现/描述操作，再通过 `tapd_call_operation` 提交对应的 `operationId` 和 `parameters`；计数可使用 `task.count`、`story.count`、`bug.count`、`timesheets.count`。目录中的操作名称与一次写入回执的 UUID 是不同用途的标识。

如需复看已有验收分析，可在服务恢复后说：

> 打开已有 TeamSight 分析 `ec2f9653-5e90-4cf1-9e8a-f95c89886fe4`，保持原快照，不重新取数。

该分析来自此前验收，范围为 2026-10-28 至 2026-11-04，包含 1 名成员、8 个工作项；它用于复查卡片与导出，不代表当前团队的最新状态。
