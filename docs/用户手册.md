# TeamSight 用户手册

跨项目团队排期看板：通过 TAPD Open API 只读聚合多个项目的任务与缺陷，按团队成员分组展示日级排期。

## 1. 只读约束

TeamSight 对 TAPD **只做读取**，不修改任何数据。实际调用的接口如下（全部为 GET）：

| 接口 | 用途 |
| --- | --- |
| `/quickstart/testauth` | 凭据连通性测试 |
| `/workspaces/user_participant_projects` | 读取当前令牌用户参与的项目列表 |
| `/workspaces/users` | 读取项目成员目录（工号 → 姓名） |
| `/tasks`、`/tasks/count` | 读取任务与数量（用于分页收敛） |
| `/bugs`、`/bugs/count` | 读取缺陷与数量 |
| `/timesheets`、`/timesheets/count` | 读取每日花费及任务累计花费 |

Rust 侧唯一的 HTTP 入口是 `tapd_get`，只用 `ureq::get` 发起请求；不存在创建、更新、删除、写回 TAPD 的代码路径。

## 2. 环境要求

- macOS（本轮打包验证平台为 Apple Silicon）
- Node.js 22+、pnpm 10+
- Rust 工具链（`rustup default stable`），仅桌面端开发与打包需要

## 3. 快速开始

```bash
pnpm install        # 安装依赖
pnpm tauri:dev      # 启动桌面端（推荐，唯一能拉取真实数据的运行环境）
pnpm dev            # 仅浏览器：可看界面、做视觉验收，但无法拉取真实数据
```

桌面端首次启动后进入「设置」页完成三步配置：

1. 粘贴并保存 TAPD personal token（可用「测试连接」验证）。
2. 「读取我的 TAPD 项目」→ 添加需要的项目 → 勾选启用（新增项目默认禁用）。
3. 「加载成员候选」→ 搜索并添加要展示的成员（看板只显示这些成员的任务）。

已添加成员可拖动手柄，或使用「前移／后移」调整顺序，操作后自动保存。看板成员分组、工时矩阵及成员筛选选项均按该顺序展示；只调整顺序不会重新请求数据。新增成员排在末尾。

## 4. 配置与凭据

配置文件位于应用配置目录（macOS：`~/Library/Application Support/com.haolinhom.team-sight/`）：

- `settings.json`：项目列表、颜色、启用状态、展示成员和工时规则（非敏感）。
- `credentials.json`：TAPD 令牌（**当前为本地明文，权限 0600**；后续会替换为系统钥匙串，接口保持不变）。

令牌解析顺序（桌面端）：

1. 应用内保存的 `credentials.json`
2. 环境变量 `TAPD_PERSONAL_TOKEN`
3. 仓库根目录 `.env.local` 的 `PERSONAL_TOKEN`——**仅开发（debug）构建生效**，发布版不读取该文件

浏览器模式（`pnpm dev`）没有桌面能力：令牌与设置只存在浏览器 localStorage，仅供界面调试。

## 5. 看板使用

- **时间范围**：默认当前自然月；可改起止日期或点「上一月/本月/下一月」。只有时间范围变化会重新请求 TAPD。
- **筛选**：项目/成员/状态多选，作用于已获取数据，不触发网络请求；状态选项来自真实数据（任务与缺陷分别分组，含自定义状态）。
- **成员分组**：每个成员一组，任务各自独占一行；同一任务有多个已配置负责人时会在各成员下各占一行；取消勾选成员会隐藏其分组。
- **完成态**：状态为 `done`/`closed`/`resolved`/`rejected` 的任务条颜色变浅（自定义中文状态不参与判定）。
- **提示与详情**：悬停任务条显示即时提示（项目/负责人/状态/优先级/预估工时/日期）；点击后在底部信息条查看要点并可「打开 TAPD」。

### 5.1 每日工时

导航「工时」打开成员 × 日期矩阵，默认当前自然月。过去日期只看实际填报；今天与未来看已填报加剩余任务分配。红色表示不足，绿色表示达标或预计充足，黄色表示排期超额，灰色表示非工作日、豁免或数据待确认。预计充足不代表实际已达标。

点击日期格查看项目、任务、状态、实际和当天分配；明细项目筛选不会改变全天汇总。成员列的待安排入口列出逾期、缺日期、缺预估等任务。已结束任务不再分配剩余量；逾期未结束任务不会自动结转今天，需在 TAPD 调整排期。

设置 → 工时统计：每日规定工时默认 **8 小时**，可改为大于 0 的小数，保存后立即重新计算并持久化。还可维护节假日／调休、成员整日豁免、自定义结束状态（填写 TAPD 状态原值）。保存失败不会覆盖已保存规则。

统计只纳入已启用项目的任务和缺陷，单位按小时；日界为北京时间。实际工时归填报人，包含任务当前排期范围之外的填报。多人任务按全部负责人均分预估后扣个人花费，超额者退出，任务总剩余量按其他人的剩余份额比例分配。跨日任务先补每日目标，再将余量留给后续日期，截止日无法容纳的余量保留并提示超额。

工时页按配置成员查询工作项，覆盖其跨月、缺日期和逾期任务；累计记录按未结束工作项单独查询并发不超过 3。首次加载可能比排期看板更久。接口失败或分页触顶会标记待确认，不能把漏数当成零。展示范围沿用看板的日期范围上限，单任务超过 366 天的预计排期列入待确认。

## 6. 构建与打包

```bash
pnpm build          # 类型检查 + 前端生产构建（产物 dist/）
pnpm tauri:build    # 桌面端打包（产物 src-tauri/target/release/bundle/）
```

打包产物：

- `bundle/macos/TeamSight.app`
- `bundle/dmg/TeamSight_<version>_aarch64.dmg`

**未做代码签名**：首次打开需要右键 App → 「打开」，或在「系统设置 → 隐私与安全性」中允许。`.dmg` 传给同事时同样需要这一步。

发布版行为差异：不读取 `.env.local`，因此必须先在应用内保存令牌（或设置环境变量 `TAPD_PERSONAL_TOKEN`）。

## 7. 故障排查

| 现象 | 原因与处理 |
| --- | --- |
| 提示「凭据无效，请重新配置令牌」（HTTP 422） | 令牌失效或格式不对：到设置页重新保存；确认使用的是 personal token 而不是 Basic 账号口令 |
| 某项目提示「无访问权限，请确认令牌所属公司与项目匹配」（HTTP 403） | 该项目的公司域与令牌不匹配：从设置页移除该项目，其余项目数据不受影响 |
| 浏览器模式看不到任务 | 预期行为：TAPD 的跨域预检不支持 `Authorization` 头，且方案禁止把令牌放 URL；请用桌面端，或 `VITE_BOARD_FIXTURE=1 pnpm dev` 看固定验收数据 |
| 提示「读取凭据失败：凭据文件格式异常」 | `credentials.json` 损坏：删除该文件或到设置页重新保存令牌 |
| 提示「尚未配置展示成员，任务会全部隐藏」 | 到设置页添加成员；设计如此（只展示配置成员的任务） |
| `pnpm tauri:dev` 启动失败、提示端口被占用 | 5183 被其它进程占用：先停掉旧的 dev server 再启动 |
| 打包后窗口空白 | 确认 `pnpm build` 通过；发布版资源由 `dist/` 内联，构建失败会导致空白 |
| Gatekeeper 阻止打开 | 未签名产物：右键「打开」，或 `xattr -dr com.apple.quarantine <App 路径>` |

日志位置：桌面端 Rust 侧诊断日志输出在启动它的终端（每次请求打印一行 `[tapd_get] GET <path>`，不包含参数值与令牌）。

## 8. 验收与回归

```bash
pnpm test                    # 单元 + 组件测试
pnpm build                   # 类型检查与构建
pnpm verify:secrets          # 令牌泄漏审计（扫描 dist/、release 产物、文档）
node scripts/verify-hours.mjs --snapshot # 只读工时接口与真实聚合核对
VITE_HOURS_FIXTURE=1 pnpm dev # 工时页演示数据（不访问 TAPD）
pnpm verify:tapd             # 只读接口能力验证（需 .env.local 真实凭据，人工执行）
VITE_BOARD_FIXTURE=1 pnpm dev    # 固定验收数据（视觉回归）
VITE_BOARD_FIXTURE=stress pnpm dev  # 2000 条压测数据（性能回归）
```

验收清单（技术方案 §12 逐项）见 `artifacts/report` 下阶段4 测试报告。

## 9. 已知边界与后续工作

- **排期看板不展示未排期任务**（工时页会列入待安排）：缺日期任务需要 `due=null`/`begin=null` 单独拉取（单项目量级上千条、且 owner 不支持多值查询），收益不匹配，暂不实现。
- **Windows 打包未验证**：代码保持跨平台可编译（权限设置走 `cfg(unix)` 分支、路径统一用 Tauri API），但未在 Windows 上构建与运行过。
- **代码签名/公证未做**：需要 Apple 开发者证书后才能消除 Gatekeeper 提示。
- **未引入虚拟滚动**：2000 条压测下表现达标（见阶段4 报告），暂不需要。
- **未做 CI/CD**：所有验证命令目前均为本地人工执行。
