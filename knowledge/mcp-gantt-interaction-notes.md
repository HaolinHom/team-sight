# MCP 甘特图工时关联、虚拟排期与交互

> 适用版本：MCP 0.3.0。2026-11-06 按展示转换、Apps 及导出源码复核；本轮未重新执行业务或原生宿主交互验收。

## 单日工时与任务关联

- 每成员每天一个工时盒子，横向限定当天日期列，纵向从第一条到最后一条关联任务行；关联取当天真实排期、虚拟区间及非零实际／预计工时贡献任务的并集，中间不连续任务行不拆段。盒子高度不表达小时数；连续虚拟区间覆盖不代表每天都有实际投入。
- 不再把缺失工作项统一汇总到成员底部占位行；各实际工时来源使用独立任务行及补充块。无有效排期且该成员在完整分析区间无正数、有限实际工时的任务不展示名称行。仅负责人包含该成员、其他成员有工时或任务已完成，均不能单独构成展示资格。当天无关联任务时在成员标题行显示状态。
- 有效真实排期与视图区间相交时，该成员没有实际工时也保留任务行；已完成任务有真实排期或本人实际工时补充区间时同样展示。无有效排期但本人有实际工时，沿用首末投入日连续虚拟条，再按视图区间过滤。
- 通过项目、类型和任务 ID 关联工时；传入共享布局的私有 ID 保持原 ID 排序并消除跨项目／类型的键冲突，不修改原始工作项。几何坐标来自共享布局结果。
- 状态依赖分析快照的 analysisDate 和既有工时数据，不重新计算业务工时。目标为零优先视为达标；其他日期有未知状态、原因或非有限总值时显示未知；其余按总数与目标判断，达标绿色、过去不足红色、当天及未来不足橙色。

## 工时关联资料与虚拟排期

- 不能只凭工时盒子高度判断工作项没有排期；当前负责人可能已流转，实际贡献者不一定出现在当前负责人任务快照中。
- `TeamAnalysis.contributionItems` 是可选的展示资料集合。新分析完成原工时和风险计算后，从所选成员的正数有限实际工时中找出快照缺失引用，按项目＋类型＋ID 去重补查；沿用 TAPD 请求队列和取消信号，最多 3 个资料读取 worker。资料不进入 `snapshot.tasks`，不新增预测、待安排量或风险。
- 缺少有效排期（双日期空、单边日期空、日期倒置或非法日期）时，按该成员在完整分析区间内的首末实际投入日生成连续虚拟条，中间无工时的日期也连起来。
- 有有效排期时，当前负责人保留真实条，排期外实际投入仅补对应单日；其他工时贡献者只在各实际投入日补块，不把原排期整个复制到其分组。
- 同一成员同一工作项一行，可以有多个条，按展示开始日期排序。布局使用私有克隆与展示日期，原始任务日期、当前负责人保持不变。虚拟排期只供展示，不写回 TAPD，不参与排期计算或模拟调整，也不额外读取分析区间外历史。
- 虚拟条沿用项目颜色与虚线边框，窄条标“补”，宽条标“按工时补充”；图例、悬浮和详情说明含义。每日实际工时仍来自原始记录。
- 资料失败或旧分析没有资料时，各来源按独立类型、ID 及投入区间展示并提示资料未获取。新分析的失败资料保留配置项目名称／颜色；旧分析缺少这些字段时从同项目已有任务回退，再回退到项目 ID／灰色。资料失败不将已知实际工时改为未知。
- 旧分析只读兼容，读取时不得触发在线补查或改写；具名验收应生成新分析。

## 过滤、分页与导出

- `buildGanttDisplayTasks` 先根据完整分析范围建立区间，`filterGanttDisplayTasks` 再过滤成员、项目与视图日期。成员范围考虑当前负责人和工时贡献者，日期匹配考虑真实与虚拟区间；仅从过滤后有展示区间的成员＋工作项生成任务行。过滤先于任务计数与分页，空任务不占分页额度。
- 仅从有效展示区间生成任务行，不能用旧空名称行标记恢复隐藏任务。任务／工时模式及 SVG、PNG、HTML 甘特图共用此规则；不改变原任务、工时计算、待安排量及风险。
- `teamsight_read_analysis` 合并展示资料，返回可选的成员展示区间信息，每页最多 200 条任务。保留完整 span 边界供详情，绘制时再裁剪到视图范围，不能用缩窄后的日期重新推断首末投入日。
- MCP 甘特图与 SVG、PNG、HTML 导出共用 core 展示转换及每成员每工作项一行的布局。导出先对完整展示行按成员／展示日期排序，再按 30 行分页；日期按 30 天分页，跨日期页仍沿用完整分析区间依据。
- 导出虚拟条标识和区间与交互甘特图一致；SVG 标题保留完整名称、真实日期、虚拟区间、当前负责人、填报成员及每日实际贡献。HTML、PNG 从同一 SVG 结果生成，静态名称行沿用截断规则。

## 层级与详情交互

- SVG 通过绘制顺序控制层级，只有优先层可点击、悬浮及进入键盘焦点。任务优先时任务不透明置顶，工时盒子淡化；工时优先时任务淡化，工时盒子的实色边框、侧带和标签置顶，内部透明以保留任务轮廓。
- 任务与每日工时详情共用右侧原生 dialog 抽屉，应用补充焦点循环及关闭后恢复。宽屏 400px，540px 以下全宽，正文独立滚动；关闭后保留图表横纵滚动位置。
- 每日详情区分“排期覆盖”“虚拟区间覆盖”与“工时贡献”，不能将区间覆盖解释为当天已填报工时。任务简讯及详情区分真实排期、虚拟区间、当前负责人、填报成员与逐日实际工时；虚拟区间详情明确提示并非每天都有工时。
- 键盘聚焦可能触发图表或宿主滚动，应延迟定位提示；已出现的提示在后续滚动时关闭。切换模式或收到新分析时清理旧详情及提示。

## iframe 可见区域

iframe autoResize 不保证整个 iframe 处于宿主可视区域。仅使用 fixed/top:0 的抽屉可能被宿主滚动裁剪。观测固定探针的 IntersectionObserver intersectionRect，可将抽屉及提示限制在 iframe 实际可见区域；这一实现已在隔离 SDK 浏览器宿主的明暗主题、窄屏和长列表中实查。不能据此承诺所有宿主行为一致。
