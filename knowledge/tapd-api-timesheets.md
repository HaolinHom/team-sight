# TAPD 工时查询与每日统计

> 验证日期：2026-10-14｜来源：真实 TAPD 只读接口、实现与自动测试。2026-10-16 经用户授权提升，并核对当前源码。

## 已验证接口事实

- GET /timesheets 返回 data 中的 Timesheet 包装对象；GET /timesheets/count 返回 data.count。
- 统计字段为 id、workspace_id、entity_type、entity_id、owner、spentdate、timespent、is_delete。样本花费值可按小时数解析；项目单位仍需服从业务约定，接口字段本身不证明所有项目统一单位。
- spentdate=YYYY-MM-DD~YYYY-MM-DD 闭区间在真实样本中有效。读取每日实际时应独立按花费日期查询，不能只从排期落在当前窗口的任务推导实际花费。当前实现的每日实际查询截止日为展示结束日与计算日的较早值，不据此承诺接纳未来填报。
- 工时 owner 不一定含工号后缀。样本中全部工时 owner 能精确匹配 /workspaces/users 的 UserWorkspace.user；目录中无稳定工号的旧账号也可能填报工时。不要仅因无工号将其花费从任务累计中丢弃。
- /tasks 的 owner 与 /bugs 的 current_owner 单人筛选在真实样本有效，可按已配置成员收窄查询工作项，同时保留跨月、缺日期与逾期工作项。多人字段不能一次传多个负责人做并集，沿用已有知识约束。
- 未结束工作项累计花费应按 entity_type、entity_id 和截至计算日的 spentdate 闭区间独立读取，不能按当前负责人过滤；历史实际归填报人，累计花费用于扣减任务总剩余量。

## 已验证实现模式

- 记录按项目 ID 和记录 ID 去重，删除标记为 1 的记录不计，实际统计仅使用 task/bug。
- 短页可用于分页收敛，满页时使用 /count；count 不可用时继续至短页。重复分页或达到 50 页安全上限必须标记不完整，不能把截断数据当完整数据。
- 校验累计查询返回记录的关联工作项，避免接口忽略筛选时误扣剩余工时。无法解析日期、工时或身份时保留完整性问题。
- 每日实际与任务累计读取分开；两者重叠记录仍按项目及 ID 去重。实际按花费日期和填报人汇总，预测按全部负责人份额计算。
- 计算先覆盖任务完整区间及竞争同日容量的工作项，再裁剪展示范围，确保同一日结果不受显示月份影响。
- 累计或负责人身份不完整时不能给出确定预计不足结论。逾期工作项累计读取失败时，待安排剩余量也必须显示未知。
